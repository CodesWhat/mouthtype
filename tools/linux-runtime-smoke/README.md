# Disposable real Linux CPU proof

This is a verification-only workflow for a draft PR. Close the PR after collecting evidence rather than merging the model-download workflow into the product by default. It has read-only repository permissions and a 30-minute deadline in a pinned Arch container on an Ubuntu24.04 hosted kernel. No local runtime/VM/container is started, and no user recordings, microphone, desktop app, private transcripts, secrets, weight cache, or publication step is involved.

The remote script installs normal signed Arch prerequisites, then runs the build, package installation and inference as an ordinary dedicated user, builds the exact official llama.cpp revision in the existing pins, installs exact sherpa versions in a temporary virtual environment, downloads only the exact official Parakeet INT8 archive and publisher S1-mini GGUF, validates their SHA-256 digests, and prepares the existing engine harness. It uses explicit curl/build/install deadlines. It retains only generated synthetic fixtures, the report and environment metadata in a 14-day CI artifact. It deletes its temporary source/build/virtual environment/models on normal completion or error; the hosted runner is disposable after the bounded job. No weights are cached or uploaded. The installed Arch package signature policy is recorded and unchanged. Missing wheels fail installation rather than downgrading Python or weakening checks.

Two newly generated eSpeak-NG utterances and one second of synthetic silence supply the three WAV inputs. They are converted to16kHz mono PCM16 using SoX. Cleanup uses three unchanged existing synthetic benchmark fixtures: filler-01, selfcorrect-01, clean-01. Expected values are fixed before inference and the exact comparator is unchanged. This tiny set establishes loading/completion and narrow quality observations, not an accuracy bake-off or Mac pipeline parity.

The real report, fixed synthetic inputs/expected outputs, actual host/CPU/RAM/tool/package versions, runtime revisions, hashes, timings, memory, and cleanup assessment appear in CI logs for inspection. Assessment separately states runtime completion and exact accuracy. Mismatches leave the job failed even if all native inference completed. Missing/unavailable/error/deadline results, fake engines, wrong Linux/architecture metadata, runtime/hash mismatches, missing/duplicate cases, and surviving owned engine processes cannot be reported as successful runtime proof. No assertion/default is adjusted to obtain a green result.

`bash tools/linux-runtime-smoke/run.sh` refuses to run outside the coordinated Linux GitHub Actions job. Host-only validator tests use `python3 -m unittest discover -s tools/linux-runtime-smoke -p 'test_*.py'` and perform no downloads or inference.

The engine/model provenance is already recorded in `tools/linux-engine-proof/pins.json`. Build choices follow the [pinned official llama CPU guide](https://github.com/ggml-org/llama.cpp/blob/6420cf5dd588c68e48657a0bbd82bb3bd5ac7209/docs/build.md); synthetic WAV generation uses the [official eSpeak command-line options](https://github.com/espeak-ng/espeak-ng/blob/master/src/espeak-ng.1.ronn). The earlier Ubuntu attempt completed inference but passed only five of six exact fixtures: selfcorrect-01 returned “3” where “three” was required. This Arch run preserves that expected value and the unchanged comparator. A completed runtime with this mismatch still fails the job.

CPU inference here does not certify cancellation during every native path, desktop capture/shortcuts/delivery, a Linux app, or distribution packaging.

The workflow runs on its narrow PR paths or by explicit manual dispatch. It creates no recurring schedule, installed desktop service or release artifact. Headless PipeWire/Sway component evidence is separate; neither this container nor the hosted Ubuntu kernel is an Omarchy/Hyprland desktop acceptance test.
