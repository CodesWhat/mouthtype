# Settings

RC.1 includes **Settings…** in the Mouthtype menu. Command-comma opens the same window while Mouthtype is active.

The daily menu contains Settings, Paste Last, Copy Last, Clean Selected Text…, Transcribe Audio File…, Saved Recordings (when there is something to recover), a collapsed Recent Dictations submenu (when there are takes), Check for Updates… (Update Available… when an update is waiting), How to Use Mouthtype…, About and Quit. Stop and Cancel appear during hands-free recording. Healthy model and permission lines stay out of the menu; an attention message opens Diagnostics when something needs repair. Recent items copy their full text and exclude secure fields. Stats live inside Recent.

**Transcribe Audio File…** is also available in the menu. Choose one WAV, AIFF or M4A file, then explicitly Copy or Save Text. See [file transcription](FILE-TRANSCRIPTION.md) for limits and cancellation behavior.

**General** contains the existing dictation shortcut, cleanup level, recording sounds and launch-at-login controls. Changing the shortcut opens the native recorder. Fast and Thorough show their actual download/loading state; dictations use Basic while the selected cleanup model is unavailable. Launch at login reports when macOS approval is still needed. Advanced delivery lets you explicitly enable split long pastes for supported terminal applications. It starts off, applies to the chosen terminal’s windows and does not identify the command-line program inside them.

**Microphone** is in General. Choose **System Default** to follow macOS, or select a microphone for Mouthtype only. The explicit choice is remembered by its persistent device identity, so reconnecting it under a new runtime ID keeps the choice. This does not change the Mac's system input. Use Refresh inputs after connecting a device.

An unavailable saved microphone stays selected and visible. Reconnect it or explicitly select another input; Mouthtype does not silently record from a different microphone. An unreadable saved choice is retained until you explicitly choose a replacement. Changing the setting applies to the next dictation and does not replace an active capture. Preparation coalesces one newer selection, rejects stale completion and remains unready if choices keep changing. Physical device switching and Bluetooth acceptance remain unverified.

**Priority list** is an opt-in microphone choice. Order connected inputs and separately choose whether System Default may be used when none are available. The first connected listed input is chosen at the start of a take. Fixed-device choices keep their explicit missing-input behavior. See [writing tools](WRITING-TOOLS.md) for limits.

Choose **Hold to talk** or **Press to toggle** under Recording behavior beside the shortcut. Hold is the default: keep the shortcut down while speaking and release to finish. Toggle starts on one press, ignores release while you speak and finishes on the next press. Your chosen key stays the same. Changing behavior cancels an active recording instead of inserting it. If the listener cannot change mode, the previous mode remains saved and Settings shows the error. Caps Lock keeps its existing toggle behavior in either mode; its system state may also change. Escape cancels unless Escape itself is your chosen shortcut; use Cancel Dictation in the menu in that case. The pill and menu retain Stop and Cancel.

**Live words** in General is off by default and applies to the next recording. While recording, it shows provisional recognition above the pill without replacing the meter or Stop and Cancel. It uses recent audio and may change or omit earlier words. Only the ordinary full-take result is cleaned up and inserted once after stopping. Cancelling discards the preview. Preview text is never added to history or inserted into another app. The current Parakeet engine reuses loaded model weights; no additional model download is required. Preview and final recognition share one inference permit. New previews are skipped while the model is busy. A final request waits for an already-active preview to finish or acknowledge cancellation, then takes priority over new previews. Preview input is bounded to eight seconds of audio; that is not an eight-second processing deadline. The wait depends on model execution and hardware. Final requests retain their order and normal full-take cleanup and insertion.

Updates are in General and **Check for Updates…** is also in the menu. Automatic checks are on by default without a prompt; turn them off in General. You choose when to download and install; automatic installation is disabled. Checks wait while dictation, recovery or file transcription is busy. Scheduled offers update the menu and Settings without raising a window; choose Review Update… in Settings (Update Available… in the menu) when you are ready. If you agree to install while a take is running, installation waits for it and queued processing to finish, then pauses new recording and replay work until the update completes or is cancelled. Unconfigured source builds and diagnostic runs never start the updater.

**Writing** contains the default tone, app rules, website rules and the existing filler, spoken-command and number switches. Tone changes capitalization and ending punctuation. Formal also removes swearing, and does not otherwise authorize paraphrasing. Cleanup Off bypasses these settings. Advanced writing preserves learning from corrections, lowercase sentence starts, final full-stop removal and raw dictionary editing. Custom tone combinations remain available. Raw file actions use your Mac’s default editor and preserve unreadable originals.

**Boost my saved words while recognising** in Writing is off by default. It makes the speech model favour the spellings in your dictionary, so a name you saved comes out right while recognising instead of being fixed afterwards. The first time you turn it on, Mouthtype downloads an extra speech model of about 100 MB (Parakeet CTC 110M, CC BY 4.0, see the third-party notices) and the line under the switch shows the download, then ready. Until it is ready, and whenever it fails to download, load or answer within 1.5 seconds, dictation uses the ordinary transcript, so a take never fails because of it. It uses up to 200 saved spellings, starred ones first, with the heard forms you saved as aliases. It rescores the finished Parakeet transcript against the audio, so it is not live in the preview, and the model is English, so it helps English names best. Replaced words keep the times of the words they replaced. The spellings applied to a take are saved with it in history. Turning the switch off unloads the extra model. Whisper engines use the same switch as a prompt hint instead, with no extra download.

App rules start empty. Choose **Add application…**, select an application, then choose its tone, its cleanup level or both. Cleanup is a second picker (Use default, Off, Basic, Fast or Thorough) that overrides the General cleanup level for takes that start in that app. A rule can turn cleanup on for one app even when the default is Off. A rule whose cleanup needs a model that isn’t installed runs as Basic, the same as the General setting, and the take records the level that actually ran. The app where recording starts determines the rule for that take. Apps without a rule use the default tone. Choose **Use default** for both pickers or remove a row to clear its override. Selecting an application that already has a rule keeps its saved tone and cleanup level. A per-app browser rule applies to that browser. Website rules can override it for a matching HTTP/HTTPS domain and subdomains when the focused window exposes its document URL. The most specific domain wins, then the app rule, then the default, and tone and cleanup level each fall through on their own: a website rule left on Use default for cleanup takes the app rule’s level. Missing URL support falls back; document URLs are not retained. See [writing tools](WRITING-TOOLS.md). Rules change tone and cleanup level, not the dictation or paste shortcut. Unreadable saved rules are kept intact and cannot be overwritten from the editor; Reload retries after repair.

**Appearance** contains the pill style (Classic, Hi-Fi, Glass, Matrix or Minimal), Pill size, a Hi-Fi readout colour and text fonts. A live preview uses the app's actual pill drawing over a Light or Dark swatch. Glass uses the system glass material and goes solid only under Reduce Transparency or when the material is unavailable. Delivery cards are drawn for the chosen style and scale with Pill size; Hi-Fi has its own pixel-art card. Readout colour is Amber, Cool white or Red and applies to Hi-Fi only. Pill size is Automatic, Standard or Large and applies to every style. Automatic chooses Large when the screen the pill appears on is at least 2000 pt wide and Standard otherwise; Large draws everything at twice the Standard size (Hi-Fi at 292×64 pt). Sizes are in points, so Automatic only adjusts proportion on large screens. A size change applies the next time the live pill appears, and the preview shows Automatic as Standard. The text-font sample shows the selected font; Hi-Fi's bitmap readouts keep their own artwork. Choose Font opens the existing native font chooser for the same global text-font preference.

**Override individual fonts** is below the text-font choice in Appearance. It starts off. Turn it on to reveal Heading, Body and Readout family choices, each with Use base font as its default. Heading applies to the card header and pill messages; Body applies to transcripts, button labels and pill details; Readout applies to numeric text. Role sizes, weights and tabular figures are retained. These choices affect the Classic pill and delivery cards; Hi-Fi bitmap readouts keep their artwork.

Turning overrides off hides the controls and keeps their saved choices. Changing the base font preserves the overrides. A saved family that is unavailable uses the base font without erasing its name. Choose Reset fonts to defaults to clear all overrides, turn them off and restore Default. Reset stays available for saved custom choices even with overrides off; the untouched Default view keeps it hidden. Existing global presets and custom families keep their previous behavior; Choose Font edits the base family. The preview shows the active choices.

**Diagnostics** shows actual speech-model progress and retry, cleanup download/cancel and fallback state, microphone and Accessibility status with System Settings links, shortcut-listener health, Fn remapping and Globe conflicts. Custom shortcuts leave Fn behavior alone. Secure Input is explained without bypassing it. File errors retain access to their raw files. Status refreshes when the menu opens, Settings activates or Refresh status is clicked; model progress and listener health update through the existing observable services.

The sidebar opens the existing **Saved spellings** and **Phrases** editors, preserving their save, cancel and draft protection behavior. Settings changes save immediately. Command-W closes the window.

In **Saved spellings**, **Import CSV…** previews a selected UTF-8 CSV before changing the library. Use a `name` header for names alone, or `heard,written` headers for exact aliases (either column order works). For example, `shawn,Sean` replaces the exact heard name with Sean. A name-only row saves that name as both the heard and written form; it does not guess pronunciations. Quoted commas, doubled quotes and multiline fields are supported. Files can contain up to 5,000 data rows and 1 MiB, with the same 128-character field limits as manual editing.

The preview shows new rows, already-saved aliases, repeated rows and errors. Identical aliases are skipped. A conflicting alias or invalid row blocks the whole import until the CSV is fixed. **Import** adds only the previewed new spellings and preserves existing entries, their order and metadata. **Cancel** changes nothing. Save or cancel a dirty spelling draft first. If another writer changes the library after preview, cancel and choose the CSV again to review the current state.

Mouthtype also writes a `paste boundary` entry to the existing app unified log. It contains fixed categories for the boundary source, preceding-character kind, continuation-cache eligibility and separator added, plus frontmost and focused Accessibility owner process IDs. It contains no transcript, surrounding text, window title or audio. These entries support a future coordinated paste investigation; they do not prove delivery or change the destination, spacing policy or retry behavior.

## First-run setup

On the first ordinary launch with missing Microphone or Accessibility access, **Set Up Mouthtype** opens once. Permission requests follow the setup buttons. Closing it or choosing Set up later does not mark the app ready, and relaunching does not repeat the window or automatically ask for permissions. Existing users with both grants do not get an upgrade window. Reopen it from **Settings → General → Set Up Mouthtype**. A permission attention item in the menu also opens setup.

Setup presents one focused card at a time: microphone access and preparation, Accessibility, speech model, then shortcut readiness. It advances automatically only when the current prerequisite passes, skips components already ready and returns to an earlier prerequisite if it becomes unavailable. Denials and failures remain on their card with the appropriate settings or retry action. No permission is requested merely by advancing a card. Setup shows real speech download/preparation/warm-up status and a retry after failure. The speech engine’s existing download is reused. Ready to dictate requires microphone authorization and preparation, Accessibility, an active shortcut listener, no unresolved Fn/Globe conflict and a warmed speech engine. Secure Input keeps it unready. The hint follows the saved shortcut and Hold/Toggle behavior. It does not record or paste a test take. Fast/Thorough cleanup can still be preparing; Basic is used until its model is available.

Refresh status or return from System Settings to recheck permissions. A denied permission links to its System Settings pane. An authorized microphone that could not prepare can be retried. Input settings opens Diagnostics for the existing shortcut, Fn remapping and keyboard controls. Diagnostic command-line probes retain their previous permission behavior and do not show or consume first-run setup.

## Checks

The ordinary `swift test --jobs 4` command includes all package test targets, including `MouthtypeSettingsUITests`. Settings rendering runs in its own test process so synchronous AppKit drawing does not block the functional cleanup tests’ MainActor deadlines. It opens no visible window and changes no real preferences.

For native checks without running Core model replays, run `swift test --jobs 4 --filter 'MouthtypeMacTests|MouthtypeSettingsUITests|FnRemapKitTests'`. That includes the functional macOS tests, the offscreen render tests and the Fn tests. For only the rendering checks, run `swift test --jobs 4 --filter MouthtypeSettingsUITests`. All rendering tests run even when no PNG output directory is set.

To save the actual-view PNGs, run `MOUTHTYPE_SETTINGS_PREVIEWS=/tmp/mouthtype-settings-previews swift test --jobs 4 --filter MouthtypeSettingsUITests`. Change the output directory as needed. The settings render cases cover all four panes at 1000×690pt plus Toggle General, populated app styles, Large pill size and a Diagnostics attention state at 860×590pt. Setup adds individual permission, microphone preparation/failure, speech loading/failure, shortcut and ready cards, including the minimum window, without invoking permission or hardware actions. Font overrides add Default, Custom, unavailable-family/minimum-width and disabled-state renders without opening the font panel. Functional settings model/menu/setup/font tests remain in `MouthtypeMacTests`.

## Quiet other audio

**General → Quiet other audio** is off by default. Capture starts immediately. With recording sounds enabled, Mouthtype lets the start cue finish before muting the current default output. It waits for the decoded cue duration and checks playback for at most one additional second; a cue that remains active skips quieting for that take. Ending the recording cancels any pending mute. With sounds disabled there is no cue delay. On supported outputs it restores the same device after capture ends, including Stop, Escape, a discarded tap, microphone interruption and capture failure. Transcription and delivery do not keep other audio muted. Turning the option off or normally quitting Mouthtype also ends its mute.

A device that was already muted is left alone. Mouthtype never changes volume. An observed later mute or volume change gives control back to the user, so Mouthtype does not unmute that device. It checks the device UID again before restoring, rather than writing to an unrelated device that reused its numeric ID. Switching output during a recording can make the new output audible; Mouthtype only owns the original output. Outputs without a settable master mute are left unchanged and dictation continues.

Core Audio exposes property notifications, not the identity of the person or app making a change, or an atomic compare-and-set. Mouthtype registers its change listener after its own mute write and restores only if no later change was observed and the original device is still muted. Same-value writes and changes inside the registration/restore windows cannot be attributed exactly. A crash or force-quit cannot run normal restoration; check macOS output mute if that happens. This option does not pause media players or prevent call apps from hearing the microphone. Physical device behavior still needs coordinated testing.

See [writing tools](WRITING-TOOLS.md) for website tone, selected-text cleanup and microphone priorities.

RC.1 keeps System Default fallback enabled while the microphone priority list is empty. Add an input before turning fallback off. Saved Recordings loads on demand in pages; older saved audio remains reachable. Use Download to repair an incomplete cleanup-model cache.
