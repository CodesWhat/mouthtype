# Settings

Alpha.4 includes **Settings…** in the Mouthtype menu. Command-comma opens the same window while Mouthtype is active.

The daily menu contains Settings, Paste Last, Copy Last, Saved Recordings, a collapsed Recent Dictations submenu, Help, About and Quit. Stop and Cancel appear during hands-free recording. Healthy model and permission lines stay out of the menu; an attention message opens Diagnostics when something needs repair. Recent items copy their full text and exclude secure fields. Stats live inside Recent.

**General** contains the existing dictation shortcut, cleanup level, recording sounds and launch-at-login controls. Changing the shortcut opens the native recorder. Fast and Thorough show their actual download/loading state; dictations use Basic while the selected cleanup model is unavailable. Launch at login reports when macOS approval is still needed. Advanced delivery lets you explicitly enable split long pastes for supported terminal applications. It starts off, applies to the chosen terminal’s windows and does not identify the command-line program inside them.

Choose **Hold to talk** or **Press to toggle** under Recording behavior beside the shortcut. Hold is the default: keep the shortcut down while speaking and release to finish. Toggle starts on one press, ignores release while you speak and finishes on the next press. Your chosen key stays the same. Changing behavior cancels an active recording instead of inserting it. If the listener cannot change mode, the previous mode remains saved and Settings shows the error. Caps Lock keeps its existing toggle behavior in either mode; its system state may also change. Escape cancels unless Escape itself is your chosen shortcut; use Cancel Dictation in the menu in that case. The pill and menu retain Stop and Cancel.

Updates are in General and **Check for Updates…** is also in the menu. Sparkle asks permission before enabling automatic checks. You choose when to download and install; automatic installation is disabled. Checks wait while dictation or recovery is busy. Scheduled offers update the menu and Settings without raising a window; choose Review Update when you are ready. If you agree to install while a take is running, installation waits for it and queued processing to finish, then pauses new recording and replay work until the update completes or is cancelled. Unconfigured source builds and diagnostic runs never start the updater.

**Writing** contains the default tone, app styles and the existing filler, spoken-command and number switches. Tone changes capitalization and ending punctuation. Formal does not authorize paraphrasing. Cleanup Off bypasses these settings. Advanced writing preserves learning from corrections, lowercase sentence starts, final full-stop removal and raw dictionary editing. Custom tone combinations remain available. Raw file actions use your Mac’s default editor and preserve unreadable originals.

App styles start empty. Choose **Add application…**, select an application, then choose its tone. The app where recording starts determines the rule for that take. Apps without a rule use the default tone. Choose **Use default** or remove a row to clear its override. Selecting an application that already has a rule keeps its saved tone. Browser rules apply to the browser application, not individual websites. Rules change tone, not the dictation or paste shortcut. Unreadable saved rules are kept intact and cannot be overwritten from the editor; Reload retries after repair.

**Appearance** contains Classic and Hi-Fi pill styles, Hi-Fi size and text fonts. A preview uses the app's actual pill drawing. Hi-Fi size changes apply the next time the live pill appears. The text-font sample shows the selected font; Hi-Fi's bitmap readouts keep their own artwork. Choose Font opens the existing native font chooser for the same global text-font preference.

Development builds add **Override individual fonts** below the text-font choice in Appearance. It starts off. Turn it on to reveal Heading, Body and Readout family choices, each with Use base font as its default. Heading applies to the card header and pill messages; Body applies to transcripts, button labels and pill details; Readout applies to numeric text. Role sizes, weights and tabular figures are retained. These choices affect the Classic pill and delivery cards; Hi-Fi bitmap readouts keep their artwork.

Turning overrides off hides the controls and keeps their saved choices. Changing the base font preserves the overrides. A saved family that is unavailable uses the base font without erasing its name. Choose Reset fonts to defaults to clear all overrides, turn them off and restore Default. Reset stays available for saved custom choices even with overrides off; the untouched Default view keeps it hidden. Existing global presets and custom families keep their previous behavior; Choose Font edits the base family. The preview shows the active choices.

**Diagnostics** shows actual speech-model progress and retry, cleanup download/cancel and fallback state, microphone and Accessibility status with System Settings links, shortcut-listener health, Fn remapping and Globe conflicts. Custom shortcuts leave Fn behavior alone. Secure Input is explained without bypassing it. File errors retain access to their raw files. Status refreshes when the menu opens, Settings activates or Refresh status is clicked; model progress and listener health update through the existing observable services.

The sidebar opens the existing **Saved spellings** and **Phrases** editors, preserving their save, cancel and draft protection behavior. Settings changes save immediately. Command-W closes the window.

In **Saved spellings**, **Import CSV…** previews a selected UTF-8 CSV before changing the library. Use a `name` header for names alone, or `heard,written` headers for exact aliases (either column order works). For example, `shawn,Sean` replaces the exact heard name with Sean. A name-only row saves that name as both the heard and written form; it does not guess pronunciations. Quoted commas, doubled quotes and multiline fields are supported. Files can contain up to 5,000 data rows and 1 MiB, with the same 128-character field limits as manual editing.

The preview shows new rows, already-saved aliases, repeated rows and errors. Identical aliases are skipped. A conflicting alias or invalid row blocks the whole import until the CSV is fixed. **Import** adds only the previewed new spellings and preserves existing entries, their order and metadata. **Cancel** changes nothing. Save or cancel a dirty spelling draft first. If another writer changes the library after preview, cancel and choose the CSV again to review the current state.

## First-run setup

On the first ordinary launch with missing Microphone or Accessibility access, **Set Up Mouthtype** opens once. Permission requests follow the setup buttons. Closing it or choosing Set up later does not mark the app ready, and relaunching does not repeat the window or automatically ask for permissions. Existing users with both grants do not get an upgrade window. Reopen it from **Settings → General → Set Up Mouthtype**. A permission attention item in the menu also opens setup.

Setup shows real speech download/preparation/warm-up status and a retry after failure. The speech engine’s existing download is reused. Ready to dictate requires microphone authorization and preparation, Accessibility, an active shortcut listener, no unresolved Fn/Globe conflict and a warmed speech engine. Secure Input keeps it unready. The hint follows the saved shortcut and Hold/Toggle behavior. It does not record or paste a test take. Fast/Thorough cleanup can still be preparing; Basic is used until its model is available.

Refresh status or return from System Settings to recheck permissions. A denied permission links to its System Settings pane. An authorized microphone that could not prepare can be retried. Input settings opens Diagnostics for the existing shortcut, Fn remapping and keyboard controls. Diagnostic command-line probes retain their previous permission behavior and do not show or consume first-run setup.

## Checks

The ordinary `swift test --jobs 4` command includes all package test targets, including `MouthtypeSettingsUITests`. Settings rendering runs in its own test process so synchronous AppKit drawing does not block the functional cleanup tests’ MainActor deadlines. It opens no visible window and changes no real preferences.

For native checks without running Core model replays, run `swift test --jobs 4 --filter 'MouthtypeMacTests|MouthtypeSettingsUITests|FnRemapKitTests'`. That includes the functional macOS tests, all four offscreen render tests and the Fn tests. For only the rendering checks, run `swift test --jobs 4 --filter MouthtypeSettingsUITests`. All rendering tests run even when no PNG output directory is set.

To save the sixteen actual-view PNGs, run `MOUTHTYPE_SETTINGS_PREVIEWS=/tmp/mouthtype-settings-previews swift test --jobs 4 --filter MouthtypeSettingsUITests`. Change the output directory as needed. The settings render cases cover all four panes at 1000×690pt plus Toggle General, populated app styles, Hi-Fi Large and a Diagnostics attention state at 860×590pt. Setup adds pending, ready, permission-denied and model/microphone-failure renders, including the minimum window, without invoking permission or hardware actions. Font overrides add Default, Custom, unavailable-family/minimum-width and disabled-state renders without opening the font panel. Functional settings model/menu/setup/font tests remain in `MouthtypeMacTests`.
